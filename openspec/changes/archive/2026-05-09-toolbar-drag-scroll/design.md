## Context

当前工具栏组件 (`src/components/toolbar-v2/Toolbar.tsx`) 使用 `flex` 布局排列所有按钮组，没有处理水平溢出的情况。当窗口宽度不足以容纳所有按钮时，按钮被挤压或溢出不可见。

工具栏结构分为两部分：
1. 左侧可滚动区域：包含所有编辑格式按钮（撤销/重做、标题、文本格式、代码、链接、列表、其他、视图模式）
2. 右侧固定区域：使用 `ml-auto` 固定在右侧（命令面板、侧边栏切换、AI 按钮）

## Goals / Non-Goals

**Goals:**
- 用户可以按住鼠标左键在工具栏上左右拖动来水平滚动
- 拖拽过程中不会误触发工具栏按钮的 click 事件
- 拖拽时提供视觉光标反馈（grab → grabbing）
- 右侧固定按钮组始终可见，不参与滚动
- 逻辑封装为可复用的自定义 Hook

**Non-Goals:**
- 不实现触摸板/触摸屏的惯性滚动（依赖浏览器原生行为）
- 不添加滚动条指示器或箭头按钮
- 不改变工具栏的按钮布局和功能

## Decisions

### 1. 使用自定义 Hook `useDragScroll` 封装拖拽逻辑

**选择**: 将拖拽滚动逻辑提取为独立的 `useDragScroll` hook，返回 ref 和事件处理器。

**理由**: 
- 关注点分离，Toolbar 组件不需要关心拖拽实现细节
- 可复用于其他需要拖拽滚动的场景（如标签栏）
- 便于单元测试

**备选方案**:
- 直接在 Toolbar 组件内写逻辑 → 组件变臃肿，不可复用
- 使用第三方库（如 `react-use-draggable-scroll`） → 增加依赖，且需求简单无需引入

### 2. 通过移动距离阈值区分拖拽和点击

**选择**: 设置 5px 的移动阈值，超过阈值视为拖拽并抑制后续 click 事件。

**理由**:
- 避免手指轻微抖动时误判为拖拽
- 5px 是常见的拖拽检测阈值，兼顾灵敏度和容错性

### 3. 工具栏布局调整为外层 flex + 内层可滚动容器

**选择**: 将工具栏分为「可滚动的左侧区域」和「固定的右侧区域」，左侧区域设置 `overflow-x: hidden`（隐藏滚动条，通过拖拽滚动）。

**理由**:
- 右侧功能按钮（命令面板、AI）是高频操作入口，必须始终可见
- 隐藏滚动条保持 UI 简洁，拖拽交互已提供滚动能力

## Risks / Trade-offs

- [拖拽与按钮点击冲突] → 通过移动距离阈值 + `pointer-events` 或 click 事件的 `stopPropagation` 来区分，mouseup 后短暂抑制 click
- [触控设备兼容性] → 本次仅实现鼠标拖拽，触控设备的原生滚动由 `overflow-x: auto` 自然支持
- [性能问题] → mousemove 事件频率高，但 `scrollLeft` 赋值本身是同步操作，不会引发重渲染，性能影响可忽略
